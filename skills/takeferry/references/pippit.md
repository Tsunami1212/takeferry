# Pippit native canvas

TakeFerry provides the local MCP tools. The official Pippit CLI handles the signed-in account and media operations. The official Node entry handles semantic canvas commands. The active profile needs the CLI, its matching Canvas SDK entry and the writer's authorized reference directory. [Official canvas contract](https://github.com/Pippit-dev/cli/blob/main/skills/xyq-nest-skill/commands/canvas.md)

1. Get the account with `takeferry_pippit_account`. Choose the writer's team space (personal space is the string `"0"`). Keep the same account and space for the canvas, files, submission and query. Use `takeferry_pippit_models` for the current model and parameters.
2. Open a canvas the writer identified or create one with `takeferry_pippit_create_canvas`. Use the returned `canvas_asset_id` for semantic commands. A canvas's project ID is a different identifier.
3. Use `takeferry_pippit_catalog` to inspect the installed command schemas. Query `get_snapshot` with `takeferry_pippit_read`. If a reference needs uploading, use `takeferry_pippit_upload_reference` with its permitted relative filename. Use its returned `pippit_asset_id` in a native source node and read back the node's media binding.
4. Create a new video node using `takeferry_pippit_edit` and `create_biz_node`. Set the approved prompt, model and supported settings in the generation data. Use the source node IDs in order for native references. Read the result with `get_asset`. Each reference in a take also has a local file, because independent video generation uses the official CLI's media inputs.
5. Call `takeferry_prepare`. The current generation path accepts a single ordinary video with an explicit length, ratio and optional resolution, using image, audio or video references that the chosen model accepts. Review the exact files, duties, prompt, settings and cost. After the writer approves, `takeferry_pippit_submit` reserves the take before contacting the provider. A retry returns its prior state. If the receipt was lost, recover the existing thread and run and pass both to `takeferry_receipt`.
6. Call `takeferry_pippit_collect` with the same take. The bridge saves an original only after the matching thread and run succeed and return a local video. When the provider is still working, query again later. A terminal failure or an unknown state needs attention in the original account.
7. Call `takeferry_pippit_bind`. It uploads the collected file into the original space, reads the native media identity, updates the intended video node, then reads it again. A finished node must match both the stable Pippit media asset and the underlying video asset. If a writeback was interrupted, inspect the node before using `retry_edit`. If an upload receipt was lost, inspect the existing upload and supply its ID as `recovered_upload`. Neither operation submits another video.

An edit to a canvas document and a generation job are separate operations in Pippit. A local download alone leaves the destination canvas unfinished. [Official media identity rules](https://github.com/Pippit-dev/cli/blob/main/skills/xyq-nest-skill/commands/canvas-assets.md)
